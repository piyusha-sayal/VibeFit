## Gaps found in account deletion

`privacy_service.delete_account` (backend/services/privacy_service.py:418) removes: the user row, and by cascade or explicit `DELETE`, `chat_messages`, `recommendations`, `collection_items`, `action_feedback`, `chat_sessions`, `look_collections`, `saved_looks`, `look_drafts`, `look_feedback`, `beauty_goals`, `beauty_activities`, `guide_progress`, `plan_actions`, `profile_corrections`, `onboarding_responses`, `analyses`, `beauty_profiles`, `user_settings`. It also attempts to delete any stored photo objects (currently always a no-op in production since none are stored).

Confirmed gaps / open items:
1. **Firebase Authentication account is not deleted.** The backend only deletes its own `users` row; the corresponding Firebase Auth user (email, UID, sign-in provider record) still exists on Google's side after "Delete my account" completes. A person who deletes their account can still sign in to Firebase itself, though the app would re-provision a fresh, empty `users` row on next login. **This is a real deletion gap, not a legal conclusion — flag for counsel/Play review.** **Update 27 Sep 2026:** fixed in code, not yet in any build. After the server deletes the data, the app now calls Firebase `deleteUser`. If Firebase refuses (sign-in older than 5 minutes), the user is told to sign in again and repeat. The web deletion flow must do the same. Verify on device once the new APK exists.
2. **`PendingPhotoDeletion` rows can outlive the account.** By design (see the model's docstring) — they hold no `user_id` so a failed object-storage delete during account deletion is retried later even after the account is gone. In production this table should stay empty since no photos are ever really stored, but the mechanism exists.
3. Render/Neon backups: per `RETENTION_NOTE` (shown verbatim in the app), deleted data ages out of encrypted rolling infrastructure backups rather than being purged from them individually — this is disclosed, not hidden, but is a genuine limit on "immediate erasure."
4. No time-based (automatic) expiry exists for analysis results, chat messages, or onboarding data — retention is "until the user deletes it or the account," full stop.
